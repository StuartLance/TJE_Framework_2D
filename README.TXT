THE GAME
--------
You are a prisoner that has to escape 3 cell blocks. In every block you must
grab a key, open the locked door and reach the green hatch without being seen.
Guards patrol the corridors and have a vision cone (yellow when calm, red when
they have spotted you). If a guard touches you, you lose one of your 3 lives.


CONTROLS (NES style)
--------------------
  Arrows / Left stick ...... move
  Z / A button ............. sprint (hold) - fast but noisy, guards hear you
  X / B button ............. throw a pebble to distract guards
  ESC / START .............. back to menu (exit from the main menu)

  Debug keys for the presentation:
  F1 ....................... skip to next level
  F2 ....................... god mode (guards cannot catch you)


FEATURES
--------
- Stages: Intro menu (Start / How to play / Exit) -> Tutorial -> Play -> End
  screen (win or lose, with time and times caught). Fade between stages.
- Guard AI (state machine): PATROL -> ALERT ("!") -> CHASE -> SEARCH ("?")
  -> RETURN to its post. Noise (sprinting or a pebble landing) makes guards
  INVESTIGATE the place where the noise happened.
  * Vision: distance + cone angle + line of sight raycast against walls.
  * Chasing / investigating / returning use a BFS path search on the tile map.
- Levels are loaded from text files (data/levels/levelN.txt, the list of
  levels is in data/levels/levels.txt). Legend:
      # wall   . floor   , floor variant   P player start   K key
      D locked door   E exit hatch   H guard patrolling horizontally
      V guard patrolling vertically
- Gameplay values (speeds, view range, lives, pebbles...) are read from
  data/config.txt, so the game can be tuned without recompiling.
- Every image and sound is loaded only once at startup (Game constructor).
- Audio: looping chiptune music + sound effects for menu, keys, doors, alerts,
  being caught, pebbles, level exit and victory.
- Game feel: walk/sprint animations, dust when sprinting, bobbing keys and
  bubbles, screen shake + red flash when caught, smooth camera, HUD with
  lives, keys, pebbles, stamina bar, block number and timer.


CODE STRUCTURE (src/)
---------------------
  game.h/.cpp      Game class: loads assets, owns the World and the Stages,
                   forwards update/render to the current stage.
  stage.h/.cpp     Stage base class + IntroStage, TutorialStage, PlayStage,
                   EndStage.
  world.h/.cpp     World: map, player, guards, keys, pebble, progress
                   (lives, level, time), perception (guardCanSee, makeNoise)
                   and GameConfig (reads data/config.txt).
  gamemap.h/.cpp   GameMap: tile grid loaded from text, rendering with
                   camera, collisions, line of sight and BFS pathfinding.
  entity.h/.cpp    Character, Player (movement with collisions, sprint,
                   stamina, doors) and Guard (AI state machine).
  controls.h/.cpp  Keyboard + gamepad mapped to arrows/A/B/back.
  The rest of the files are the TJE 2D framework.

Assets: the pixel art (data/*.png) and the 8-bit sounds (data/sounds/*.wav,
mono 48kHz 16 bit) are generated by tools/make_assets.py.
tools/check_levels.py checks that every level is solvable.


USE OF AI
---------
I used ai as a coding assistant. The game design (theme,
mechanics, levels) was decided by me and the code was written with the
assistant following the structure proposed in the slides
(Stage / World / GameMap / Sprite classes). AI-written parts and what they do:


- world.cpp: guardCanSee() = distance < range, angle inside the cone (dot
  product with the facing vector), and line of sight. makeNoise() sends nearby
  guards to investigate. Vision cones are drawn by casting 48 rays per guard
  into a mask and tinting the masked pixels once.
- tools/make_assets.py: generates the pixel art and the 8-bit sounds/music.
- tools/check_levels.py: checks that the exit is only reachable through a door
  and that a key is reachable.
